# 参数联动关系与调参决策树

## CFG 全表（v23 基线）

| 键 | 默认（桌面 / 手机） | 作用 | 调大的后果 |
|---|---|---|---|
| `loF` | 0.113 / 0.228 | 尺寸带下限（视口宽占比） | 最小图变大，大小参差感减弱 |
| `hiF` | 0.143 / 0.26 | 尺寸带上限 | 最大图变大，占用跑道，漂移收窄 |
| `MX` | 70 / 24 | 左右禁飞区 | 中部更挤，同密度下画布更长 |
| `E` | 6 / 4 | 上下边缘安全距 | 影响很小 |
| `RES` | 15 / 10 | 每侧最小跑道（放置时预留） | 静态更疏，漂移空间更大 |
| `voidRatio` | 1.5 | 画布空隙率 | 越大越长越疏 |
| `bandsPerScreen` | 3 | 纵向带数 = 屏数 × 此值 | 越大带越细，大小混排越均匀 |
| `clusterBias` | 0.6 | 聚簇偏置概率 | 越大越成团、留白越集中 |
| `gapMin`/`gapSpan` | 6 / 8 | 呼吸间距 = min + hash×span | 越大越疏 |
| `RCAP` | 46 / 26 | 单侧漂移上限 | 动感更强，但需要更大间隙，会反向压缩密度 |
| `wxLo`–`wyHi` | 0.05–0.22 / 0.04–0.2 | 漂移角频率 | 越大越快（周期 = 2π/ω） |
| `rotSpan` / `rotAmp` | 6 / 2.8 | 静态摆角 / 摆动幅度 | 旋转更明显 |
| `dustN` / `sparkleN` | 460 / 46 | 星尘数量 | 背景更"浑浊" |
| `revealTimeout` | 5000 | 首屏兜底浮现 ms | — |
| `spacingFactor` | 1 | 间距倍率：<1 更密。按平台默认缩放 RES 与 gap | 密度升、振幅降（见制约①） |
| `speedFactor` | 1 | 速度倍率：>1 更快。只缩放角频率，不动振幅 | 更快但不更"晃"，零相交不受影响 |
| `fixScreensCap` | false | 画布屏数上限随张数伸缩（修"上限绑定→底部堆图"） | 长卷可超过 8/9 屏，消堆底 |
| `fixFallbackScan` | false | 兜底/自愈扫描步长细化（修"明明有位却垫底"） | 少垫底，但改变布局几何 |
| `fixOrbitRadius` | false | 轨道半径用满预算 (L+R)/2（修"图块锁住不动"） | 弱动图块显著减少 |
| `fixWeakMovers` | false | 弱动救济：把被包夹图块在本带内搬到净余量更大处 | 效果有限，优先用 weakRatio |
| `weakRatio` | 0 | >0 启用：速度下限 = 本页峰值速度中位数 × 此比例 | 更多图块被提频（见制约①-b） |
| `speedFloorCap` | 6 | 单块提频倍率上限 | 越小越保守，防抖动感 |
| `morph` | 0 | >0 启用重组插值 | 见下 |
| `morphSpeed` | 0.9 | 插值收敛速度 | — |

> `spacingFactor` / `speedFactor` 是**相对倍率**，作用于平台默认值（桌面 RES 15 / 手机 10）。
> 绝对覆盖（如 `RES:6`）在两端收紧比例不同（桌面 −60% / 手机 −40%），同一份 config
> 会让桌面 +23.5% 而手机只 +17.0%，结果不可比。倍率保证两端比例一致。
>
> `fixScreensCap` / `fixFallbackScan` 默认 false 以保持与 v23 逐帧等价（v23 自带这两个缺陷）。
> **开启后等价性校验会失败，这是预期而非回归** —— 此时应改用"相对 v1 实测对比"来验收。

## 核心制约关系（记住这三条，别乱试）

**① 密度 ↔ 漂移幅度 是零和的；但「速度」不在这条零和线上**
漂移预算来自实测间隙：`额度 ≈ 净间隙 / 2`，上限 `RCAP`。间距收紧 → 间隙变窄 → 每张图能漂的**距离**变短。想同时要"很密"和"漂得很远"，物理上做不到，必须选一边。

但用户说"运动更明显"时，要的通常是**速度**（px/s），不是振幅（px）。
位移 `= sin(s·w+φ)·r`，其最大速率 `= w·r`。密度提高把 `r` 压小，
只要把角频率 `w` 等比放大，净速度即可不降反升 —— **零相交只取决于半径 r，与 w 无关**，
所以提频不破坏安全保证。这是唯一能同时兑现"更密 + 更快"的路径。

补偿公式：`speedFactor ≈ 目标速度倍数 ÷ 实测振幅比`（振幅比 = 新振幅中位 ÷ 旧振幅中位）。
例：spacing=0.45 使振幅 36.6→21.0（比 0.573），要净速度 +20% → speedFactor ≈ 1.2/0.573 ≈ 2.08。

实测参考（1440×900，104 张，含 fixScreensCap+fixFallbackScan）：
| spacingFactor | 每屏密度 | vs 基线 | 兜底 | 合振幅 | 理论速 w·r |
|---|---|---|---|---|---|
| 1.0 | 13.1 | −1% | 2 | 36.6 | 4.84 |
| 0.8 | 13.9 | +5% | 2 | 29.9 | 3.90 |
| 0.6 | 15.1 | +17% | 1 | 27.0 | 3.38 |
| 0.45 | 16.3 | +24% | **0** | 21.0 | 2.81 |
| 0.4 | 16.5 | +25% | 1 | 21.6 | 2.68 |

注意两个反直觉点：
- **收紧间距反而降兜底**：area 变小 → 同 voidRatio 下画布更矮，且每块间隙占比更高，放置更易成功。降 voidRatio 则相反（画布缩 → 堆底升）。
- **密度增益 ≠ voidRatio 反比**：密度受分离地板 `(gap+gap)/2+2*RES` 约束，画布缩到放不下就垫底，增益封顶。

**①-b 「锁住不动」的唯一正确解法是提频，不是搬迁**
高密度下分离余量 ≈ `(gap+gap)/2+2*RES`，漂移预算 = 间隙/2，故必然存在一撮被四面包夹、
振幅只有几 px 的图块。实测 `fixWeakMovers`（搬位置）只把 <12px 占比从 2.0% 降到 1.5%，
因为整条带都被包夹，搬去哪都差不多。
但**可感知性 = 频率 × 半径**：同一块 r=12、w=0.069 只有 0.83px/s（看不见），
w=0.30 就是 3.6px/s（清楚）。而**零相交只取决于半径，与频率无关**（px 范围恒为
[cx+ox−rx, cx+ox+rx]），故提频不放松任何保证。
标定（1440×900）：`weakRatio=0.72` → 最慢块 1.11→4.00px/s，约 26 张/页被提速、倍率上限 4.1；
手机同参数最慢 2.49px/s。再高（0.85）会提速 38 张、频率周期逼近 7.7s，动感趋同，不建议。

**② 尺寸带 ↔ 参差感 是零和的**
`hiF/loF` 就是最大最小比。1.53（135–206）参差明显；1.27（162–206）偏均一。用户说"小图太小"就抬 loF，说"太整齐"就降 loF，不能两全。

**③ 碰撞口径决定一切**
图框级零相交（当前）比主体级严格得多，代价是漂移行程从 ~55px 收到 ~46px。若用户接受"羽化暗边可交叠"，可换回主体级换取更大动感——但必须事先告知露框风险（案例 5）。

## 调参决策树

```
用户反馈
├── "太挤 / 太空"            → voidRatio ∓0.15，跑 S3
├── "图太大 / 太小"          → loF/hiF，注意会连带改参差感，跑 S3
├── "不够动 / 动太多"        → 先调 RCAP（幅度），再调 wx/wy（速度）
│                              ⚠ 调 RCAP 会挤占密度，改完必查 voidRatio 是否需回调
├── "贴屏幕边"               → MX
├── "上密下疏 / 上大下小"    → 查 bandsPerScreen、兜底路径、H0 是否放置中变更
├── "有重叠"                 → 先确认碰撞口径是图框级；再查不动点预算是否收敛（pass<8）
├── "打开全黑"               → 查画布高度公式 + reveal 逻辑，跑 verify 看首屏断言
├── "方框边框可见"           → 查羽化 mask 与背景是否纯黑（不要加底纹）
├── "背景像脏点"             → 星尘必须纯白锐利；禁用 createRadialGradient 柔斑与前景层
└── "同步移动"               → 检查是否引入了共享平移；必须每图独立频率+相位
```
