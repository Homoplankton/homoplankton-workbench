# 同一生物关联条带（kinship filmstrip）

点开一只生物 → 同一生物的其他角度以横向胶片条铺开，可滑动平移浏览。
本文档记录**方法与格式**；分组数据本身是每个项目的产物，不进技能。

---

## 判定口径（必须由用户确认，不可自行假设）

「同一生物」在本功能里指：**同性别 + 同发育期 + 形态相似**的个体。

- 跨性别**不**归组（船蛸雌雄异形）
- 跨发育期**不**归组（无壳幼体 vs 有壳雌体——即使同种）
- 近缘种**不**归组

这个口径来自用户 2026-10-27 的明确划定。**开工前必须再确认一次**，因为口径决定一切：
若用户其实想要「同物种全发育阶段」，那应该走生长序列（另一个工具），而不是这个条带。

> 口径的直接后果：视觉相似度是主信号，不需要物种级鉴定兜底。
> 这对能力边界是好消息——物种级鉴定实测 0/10 能定到种，但「看起来像不像」不需要定到种。

---

## 核心不变量：算法只召回，人眼才判定

这不是保守表态，是实测结论。以连拍簇为地面真值（同潜次内 `DateTimeOriginal` 间隔
≤10 秒 = 几乎必然同一个体），实测 8 对：

| 方法 | 结果 |
|---|---|
| 紧阈值（d≤0.18）召回 | 50% |
| 宽网（每图前 20 近邻）召回 | 88% |
| **任意阈值下「同簇」率** | **恒为 2/8**（0.20→0.40 都是） |

即：放宽阈值只会把垃圾并成大簇，**不解决判别力**。全链接聚类在 thr=0.13 时产出
55 张巨簇且簇内最大距离 1.0（链式膨胀：A像B、B像C 就把 A-C 连进来）。

所以流程必须是：算法产出候选 → 生成接触表 → **人（AI）逐组看图判定** → 写入 kinship.json。

## 管线

```bash
# 前置：需要主体居中的图片（用于形态特征）。可复用 S1.2 的素材，
# 或单独生成一套 detail 裁剪（长边 1200，主体框 + 12% 留边）。
# ⚠ 裁剪只用于「算特征」，绝不用于「显示」——见下方教训。

# ① 形态特征 + 两两距离 + 候选对
python3 scripts/kin_features.py <主体裁剪目录> --out <项目>/kin_features.json [--limit 40]

# ② 接触表（★=主图，其后为它的 K 个最近邻，标注距离与主要差异特征）
python3 scripts/kin_sheets.py <项目>/kin_features.json <主体裁剪目录> \
        --out-dir <项目>/review_sheets [--k 8] [--thr 0.42]

# ③ 人工核验：用 Read 工具逐张看接触表，判定每组是 coherent / mixed / rejected
#    → 手写 <项目>/kinship.json（格式见下）

# ④ 注入站点（挂载层语法必须先过 node --check）
node --check assets/kinship_mount.js
python3 scripts/inject_kinship.py --mount assets/kinship_mount.js \
        --groups <项目>/kinship.json --targets <站点.html> [<站点副本.html> ...]

# ⑤ 浏览器实测（必须用真实浏览器，不是 --dump-dom）
CHROME --headless=new --remote-debugging-port=9381 file://<站点.html> &
PORT=9381 MATCH=<站点文件名子串> node scripts/test_kinship.mjs
```

`--limit 40` 用于大图库先小规模试跑（O(n²) 两两距离，108 张 5778 对约 6 秒，
3108 张约 480 万对，需分批或改用近邻索引）。

## kinship.json 格式

```json
{
  "schema": "plankton-playground/kinship/v1",
  "scope_rule": "同一生物 = 同性别 + 同发育期 + 形态相似",
  "method": {
    "recall": "特征权重与召回策略",
    "verdict": "人工核验方式与覆盖率",
    "time_signal": "连拍时间信号的口径",
    "ground_truth_note": "地面真值召回率实测数字",
    "known_limit": "已知失效场景"
  },
  "groups": [
    {
      "group_id": "<组号，如 K1>",
      "label": "<人类可读的形态描述，如 透明八腕幼体>",
      "status": "confirmed_by_visual",
      "members": ["<图片id1>", "<图片id2>"],
      "likely_members": [],
      "evidence": "写明判定依据：看了哪张接触表、依据哪些可见形态特征、各帧角度差异",
      "note": "可选：与其他工具的交叉印证"
    }
  ],
  "rejected_pairs_of_note": [
    { "a": "<图片id>", "b": "<图片id>", "d": 0.157,
      "why": "特征距离很近但目视为完全不同的生物" }
  ]
}
```

> 上面的尖括号是占位符，不是可复制的真实值。分组数据是**每个项目自己的产物**，
> 技能本体不携带任何具体图片的分组结果（`assets/kinship_mount.js` 只读
> `window.__KIN_GROUPS__`，由注入器从项目的 kinship.json 生成）。

`status` 取值（**必须用完整语义名**，`inject_kinship.py` 会归一化成挂载层的短键）：

| kinship.json | 挂载层键 | 显示徽标 |
|---|---|---|
| `confirmed_by_visual` | visual | 人工目视确认 |
| `confirmed_by_visual_and_time` | visual+burst | 目视＋连拍双重确认 |
| `confirmed_by_taxonomy_and_visual` | visual+taxonomy | 目视＋分类学确认 |
| `confirmed_by_time` | burst | 连拍时间确认 |
| `similar_uncertain` | uncertain | 相似·待你确认 |
| `user_pin` | user | 你指认的分组 |

> ⚠ 未知 status 会被注入脚本**拦下报错**（不会静默降级）。因为挂载层对未知 status
> 会 fallback 到 `uncertain`，把人工确认过的组显示成「待你确认」——这是会误导用户
> 判断的静默错误，实测踩过。

`rejected_pairs_of_note` 要如实记录：哪些对特征距离很近、但目视判定无关。
它们是这套方法的精度边界证据，也是对用户诚实的一部分。

## 特征设计（v2，勿回退到颜色主导）

判别核心是**轮廓半径函数的频谱**：从主体质心按 72 个角度（每 5°）向外射线，
记录最远前景距离 r(θ)，均值归一化后做 DFT 取幅值谱。

- 幅值谱**天然旋转不变**，均值归一化**天然尺度不变**——正好匹配「同一生物不同角度」
- 直接编码「有几条腕 / 几道棘 / 是否圆形」：章鱼八腕 → f=8 附近有峰；水母钟形 → 低频集中

权重：`spec 0.52 / hu 0.22 / topo 0.14 / color 0.12`

**v1 用颜色主导（0.42）已被否决**：黑水照片里所有胶质生物都是「黑底上的半透明白蓝」，
颜色直方图高度雷同，实测把螺壳、水母钟、带棘幼体、章鱼聚成一簇且 maxd=0.096
（全场最低之一）。颜色只配当辅助信号。

两个必须保留的修正（都是自身 bug，改回去会掉召回）：

1. **topo 特征不得含包围盒长宽比**——它对旋转敏感。同一只栉水母转 45° 后
   topo 距离达 1.60，把地面真值对拖垮（召回仅 38%）。只保留旋转不变量（孔洞数、实度）。
2. **Hu 矩必须数据集标准化，不得硬钳位**。`min(d_hu, 1.5)` 会让大量对顶到上限、
   恒定贡献 0.33 的噪声距离，淹没有判别力的项。改为 z-score + tanh 压缩。

以上两项修复后地面真值召回 38% → 50%。

## 已知失效场景（不是 bug，纯几何修不了）

- **三维姿态剧变**：八腕幼体三帧 `spec` 0.44–0.72。人靠「八条腕＋橙色色素环」认得出，
  轮廓投影完全不同。
- **变焦差异**：樽海鞘两帧 `spec` 0.76（连拍地面真值中唯一漏网的一对），
  光晕在缩放后掩膜不同，轮廓不稳。

对策：靠连拍时间信号补位，或靠人工核验时主动想到。**不要试图用调阈值解决**——
阈值扫描已证明无效。

规模上限：3108 张时宽网候选约 3.1 万对，人工策展不可行。扩量前需新机制
（近邻索引 + 分类学先验预筛），未经验证不要承诺。

## 条带 UI 的既有约定（用户已验收，勿改）

| 项 | 约定 | 为什么 |
|---|---|---|
| 图源 | **整帧展示层 `r.src`** | 640px 主体裁剪会过裁、把生物放大到占满画框、显得不真实且降分辨率（用户截图否决）。整帧保留黑水语境与真实比例 |
| 焦点放大 | 纯 `transform: scale(1.22)` | 改 `height` 会移位并破坏平移数学。实测焦点仅约 423px 高，不存在放大模糊 |
| 焦点全分辨率升级 | **不做** | `r.full` 是整帧高清图（实测 2745×4117），不是裁剪；换用会重现错位 + 长宽比跳变 + 白下载 |
| 边界行为 | 居中锁定 | 首/尾图另一侧留白，焦点永远在正中 |
| 排列 | 保留错落 | 奇偶上下错位（±stag），自然散布感 |
| image ID | 完全不显示 | 无 figcaption / 无 title / alt 空。沉浸优先 |
| 关闭 | 延迟 460ms 清理 | 覆盖 `#lb` 的 0.4s 淡出。立即拆条带会让引擎单图 `.frame` 带着上一张主图闪现 ~0.1s |
| 无关联组 | 不进条带 | 保持引擎默认单图，不打扰 |
| 无分组数据 | 整体静默关闭 | 不建任何 DOM，站点退回纯漂浮长卷 |

尺寸随组内张数自适应（`sizing(n)`）：n≤2 → 44vh，≤3 → 40vh，≤4 → 36vh，
≤6 → 30vh，≤8 → 25vh，更多 → 21vh。

## 指认纠正机制（用户自建人工核对回路）

`P` 键或右下角 ◎ 按钮进入。用户在漂浮场直接点选生物，然后：

- **声明为同一只生物** —— 合并（可跨原有分组），生成 `status: user` 的新组
- **移出所属分组** —— 把某张从 AI 分组中移除
- **导出反馈** —— 产出 corrections JSON，用户发回来即可更新 kinship.json 重建

改动即时生效 + localStorage 持久化（key `plankton_kinship_corrections_v1`）。
被指认的新组用紫色徽标区分于 AI 分组。

导出的 JSON 结构（`PlaygroundKin.exportCorrections()`）：
`{ schema, exported_at, site, counts, note, corrections:{merge,remove}, effective_groups_snapshot }`

**收到用户导出的 corrections 后**：合并进项目的 kinship.json（merge → 新增组或扩成员，
remove → 从成员列表删除），重跑 `inject_kinship.py`。不要让纠正只活在 localStorage 里——
那是易失的，且换浏览器就没了。

## 注入与测试的两个硬坑

1. **注入必须按内容特征剥离旧块**，不能按注释标记。实测按标记剥离漏掉了早期无标记的
   v3 块，导致 v3+v4 双挂载并存：8 张 `.kinfig`（4+4）、src 混合。
   `inject_kinship.py` 用 `PlaygroundKin|__KIN_GROUPS__|__KIN_CROPS__|kinwrap` 作特征，
   并断言块数与 `PlaygroundKin` 定义数（从挂载层源码推导，不写死）。

2. **注入前必须 `node --check`**。JS 不支持 Python 式相邻字符串拼接（`"a"\n"b"`），
   写错会让整个 `<script>` 块静默失效、页面毫无反应。本项目踩过两次。
   同理写脚本时留意 `global` 声明必须在首次使用之前（argparse 的 `default=X` 就是一次读取）。

测试汇报纪律：`node ... | tail` 管道下 `$?` 取到的是 tail 的退出码，会把致命失败读成
「退出码 0」。必须直接检查 node 的退出码（0=全通过 / 1=断言失败 / 2=找不到页面），
并看未过滤的原始输出尾部。
