# Larval Taxonomy

把「一张没有元数据的幼体照片」推进到「能防守的最高分类阶元」。核心纪律：**精度不靠敢报，靠敢停**。

## 硬约束（违反即视为结论无效）

1. **元数据隔离**：文件名、目录路径、拍摄者口述的类群猜测、批次标签一律丢弃，不进证据链。它们是无意义序列号。
2. **证据只有三类**：照片像素、可采纳文献（见 `references/literature-gate.md` 的来源分级）、自身知识。自身知识可以提出候选，但**不能独立支撑高于「假设」档的置信度**。
3. **每条结论必须带三件套**：证据来源（像素位置 / 文献条目 / 知识）、置信度档位、以及「什么观察能推翻它」。
4. **停层规则**：停在能防守的最高阶元。宁可报「科，属不定」，绝不硬凑到种。
5. **文献门是置信度的前提**：任何高于「假设」档的标签，必须先过文献核查。像素特征看起来再决定性也不例外。
6. **宣布即执行**：如果在推理中宣布某个判据是决定性的，它必须作为特征表的一行、显式报告其观察结果。没跑的判据 → 结论封顶在「假设」档。
7. **色素点默认是未分配特征**，不是噪声。对每个候选类群测试它是否携带眼点/色素器，再决定去留。
8. **趋同区降档**：进入多门共享幼体等级（如「单条纤毛环 + 透明软体」）时，置信度天花板自动下调一档，且头号竞争假设必须写进排除表。
9. **文献不可得则封顶假设档**：查不到可采纳来源时，只给候选清单 + 需要哪类文献，不下类群结论。
10. **禁止伪造引用**：不得凭印象给 DOI、期刊名或页码。不确定就检索，检索不到就标注「未核验」。

置信度词表（只用这几档）：`高` / `中高` / `中` / `假设（封顶）` / `不承诺`。

## 主流程

### S0 · 证据清点与元数据隔离

列出可用的证据：几张图、什么视角、分辨率与放大倍率线索、有没有比例尺。**缺哪个视角要显式记录**——缺的视角常常就是置信度的天花板。丢弃所有元数据线索。

### S1 · 轴向 + 光学伪影裁决

两件事，顺序不可换：

- **解朝向**：用户给的朝向声明（如「这是腹面」）是待验证假设，不是输入事实。用像素线索独立验证，并记录「哪个视角缺席」。若结构自标注轴向（如口前罩=前、末端纤毛环=后），本步降级为 sanity check。
- **光学 vs 结构**：黑水闪光灯下，纤毛常呈虹彩（蓝紫/金黄闪光）。裁决规则：虹彩若只沿**一条横行环带**分布 → 纤毛的光学效应；若呈**多条纵带** → 才考虑栉板类结构。同理区分「真实刚毛/刺」与「眩光条带」。这一步是黑水照片特有的强制关卡。

多视角图在此步交叉验证：用它裁决单视角定不了的归属（附肢属于哪个体节、刺着生在哪块甲、器官团块是肠还是腺体）。

### S2 · 体计划点表

先建表，再判门。**不允许跳过建表直接「看着像」**。表结构：

| 结构 | 观察（像素证据） | 分类权重 |
|---|---|---|
| 体区/分节 | | |
| 附肢或纤毛带（逐条编目：位置、单双枝、设毛、口前/口后） | | |
| 头部结构（口器、触手、眼点、顶器） | | |
| 硬部（壳、骨针、外骨骼、刺甲） | | |
| 内部（消化道形态、腺体团块、体腔） | | |
| 色素（位置、形态） | 默认未分配特征 | |

「观察」列只写看得见的事实；「权重」列写它支持或排除什么。看不见的结构记为**未确认**，不是「无」——这两者在 S7 有不同后果。

### S3 · 判门 + 双向排除表

门序列：先定大支（有无分节附肢 → 节肢 vs 软体幼体；有无触手冠 → 触手冠动物；有无脊索/鳃裂 → 后口动物），再逐门收窄。

**每道门都必须写出被排除的相似类群及排除依据**，依据落在 S2 的表上，不允许「感觉不像」。

排除表要**双向跑**：对每个候选类群，列出「它要求的特征清单」，逐条核对**存在/缺失/未确认**。禁止在第一个自洽故事处停下——这是最常见的失败模式。

黑水幼体的高频冒充者清单见 `references/lineage-cores.md`（按谱系分列）。

### S4 · 文献门

**在下结论前跑，不是在下结论后补。**

1. 按 `references/literature-gate.md` 的来源分级筛出可采纳来源。百科类、科普站、新闻稿、社交媒体、个人摄影站、博客、聚合站**一律排除**，不进证据链、也不作「佐证」。
2. 打开全文核对，不只读检索摘要。记录：来源条目、可达状态（全文已开 / 仅摘要 / 仅检索片段 / 不可达）、核验状态（全文已核验 / 仅书目 / 未核验）。
3. 关键判别特征需 ≥2 个独立来源；单源 → 标注「单源待校验」。多源矛盾 → 标注分歧，不选其一。
4. 文献只给定性描述时，不得自行补成精确数值（如具体刺数、分期期数）。

查不到可采纳来源 → 按硬约束 9 封顶假设档，并说明需要哪类文献才能往下走。

### S5 · 发育分期

按类群选分期引擎（见 `references/lineage-cores.md`）：器官出现序、计数递增、或 competence 标记。

- **给区间，不给点**，除非找到该种饲养论文的分期表可逐条对照。
- **competence（是否具备附着/变态能力）与龄期是正交两轴**，必须分开报，不得混成一个「期」。
- 分期证据缺失时写「未确认」，不要用体长反推（体长受温度与营养影响，跨文献不可比）。

### S6 · 成体重构

先判定幼体与成体的关系类型，再决定重构方式：

- **外推型**：幼体≈成体的带刺/简化版（如十足目）。可以「减去幼体甲、补全附肢」外推，并说明哪些结构消失、哪些补全。
- **导入型**：变态是灾变性的，幼体结构被销毁、成体从头建（如帚虫）。此时**不能从这张照片外推**，只能从门级体计划导入，并明说这一点。
- **对接未解决型**：文献本身未把该幼体型对接到成体（如某些星虫与樱虾科幼体）。只给科级以下不承诺，并说明这是文献现状而非我的谨慎。

成体画像永远只承诺到**能防守的阶元**，不得写成种级肖像。

### S7 · 置信度账本 + 升级清单

输出必须包含：

- 每个阶元的置信度档位与停层位置；
- 哪些结构「未确认」（区别于「确认缺失」），以及它压住了哪一档置信度；
- **升级清单**：逐项写明「补什么观察能把结论往下推一阶」，并标注每项能推到哪一层（如：补正侧+背面视图 → 读完整刺式 → 可到属；饲养至变态 → 终局；分子条形码 → 种级）。

### S8 · 人在环 + 学习闭环

我产出的类群 + 分期是**草案**。用户确认或改正后才进批注库；未确认的草案不得被下游工具（生长发育序列、关系图、图库标签）当作已核实数据消费。

**学习闭环（每次跑 SOP 都生效）**：

- **跑前必读**（若存在）：工作台项目的 `data/error_book.json`（错题集：历史误判+用户指出的漏看特征+失败模式）、`data/anchors.json`（锚点库：用户已确认的图按分类路径归档）、`data/accuracy_ledger.json`（准确率台账）。
  - **锚点比对是强制步骤**：新图与锚点库中同类群已确认图先比对再落结论——对着已确认的真实样本比对，永远强于对着文字描述想象。
  - 错题集中与当前谱系相关的失败模式，要在 S3 排除表里显式自查（"我这次有没有重犯 eb0XX？"）。
- **跑后必做**：提醒用户裁决路径（工作台内 1/2/3 + 备注「你漏看了什么」→ 顶栏保存导出 → 放入 `data/decisions/` → 跑 `scripts/ingest_feedback.py`）。
- **摄取纪律**：人工判决永远压过 AI 草案（confirmed/human，AI 不得再覆盖）；被推翻的旧值保留在修正链；错题集的失败模式归类只是**建议**（关键词启发），一律标 needs_human_review，写进 `references/failure-cases.md` 前须经用户确认根因。
- **批次纪律**：每批 20–40 张；每批交付草案 + 准确率报告（对上一批的变化、按类群与失败模式分解）。台账只记事实，不粉饰。
